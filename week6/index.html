Week 6: More JavaScript

Last week we covered variables, DOM selectors, and basic event listeners — enough to click a button and change something small on the page. This week we'll learn more about Javascript as a programming language, so that we can do more complicated tasks with it.

Also notice this class assumes you have basic knowledge in another programming language (Python), so that we won't teach you the basic programming concept, but focus on what's special in JavaScript.

1. Data Types

JavaScript is a dynamic language with dynamic types. Variables in JavaScript are not directly associated with any particular value type, and any variable can be assigned (and re-assigned) values of all types:

let foo = 42; // foo is now a number
foo = "bar"; // foo is now a string
foo = true; // foo is now a boolean

JavaScript is also a weakly typed language, which means it allows implicit type conversion when an operation involves mismatched types, instead of throwing type errors.

const foo = 42; // foo is a number
// JavaScript will automatically convert foo to a string
// so it can be concatenated with "1"
const result = foo + "1"; 
console.log(result); // 421

Other common data structures are:

  • Arrays: JavaScript arrays are resizable and can contain a mix of different data types.
  • Objects: JavaScript objects are used to store various keyed collections and more complex entities. JavaScript object keys are always strings, but this is handled for you.

const array = [1,2,3]; // this is an array
array = [1,true,"3"]; // different data types are also fine
array.push("one more item"); // use .push() to append item to an array

// this is a javascript object, it is the closest equivalent to a Python dictionary
const student1 = {
    name: "Peter",
    age: 23,
    hobbies: ["cycling","reading","dreaming"],
    registered: true
}; // notice there is no need to wrap the key inside "", this is handled for you.
console.log(student1.name) // and you can access the value of a key using object.key
// to add new entry to object
student1.email = "peter@leuphana.de";

2. Functions

JavaScript offers various ways to define functions, each with its own strengths and use cases.

Declaring a function

This is the most common way to define a function that you want to reuse. In Javascript the convention is to use camelCase when it comes to naming a function.

The special thing about this way of defining function is that they can be called before they are declared. This is because Javascript will evaluate all the function declaration before checking other 

// Function declaration — the classic way
function greetPerson(name) {
    return "Hello, " + name + "!";
}

// Calling the function
console.log(greetPerson("Mona"));   // "Hello, Mona!"
console.log(greetPerson("Lee"));    // "Hello, Lee!"

Function expressions

You can also define a function by saving it to a variable, this is called function expression. However, if you define your function in this way, you have to define it first before you call it. Check this codePen for a demo compararision between the two.

// Function expression — store a function in a variable
const greet = function(name) {
    return "Hello, " + name + "!";
};

Arrow functions

Arrow Functions were introduced in ES6 and are commonly used in modern JavaScript. It allows a shorter syntax for function expressions. With this format, you can skip the function keyword, the return keyword, and the curly brackets. We won't use it so much in this class, as it's not so beginner friendly. 

// Arrow function — shorter syntax, same behaviour
const greet = (name) => {
    return "Hello, " + name + "!";
};

// Even shorter: if the body is a single expression,
// you can drop the braces and the `return`:
const greet = (name) => "Hello, " + name + "!";

Anonymous Function

An anonymous function is a function without a name, mainly used for specific or short-term tasks. These anonymous functions are just about everywhere in JavaScript, mostly in:

Event Handlers

We have seen this in our previous session:

document.getElementById('btn').addEventListener('click', function() {
    console.log('Button clicked!');
});

Callbacks

Callbacks are functions that are passed as an argument onto another function, to be executed once some condition is met or an operation is completed.

setTimeout(function() {
    console.log('This runs after 2 seconds');
}, 2000); // setTimeout is like delay() in Python

Immediately Invoked Function Expressions (IIFE)

These functions execute immediately after definition. The following pattern is very common. It is used to create a new scope and not pollute the global scope. 

(function() {
  console.log('This function runs immediately!');
})(); // The first set of '()' defines the scope
// while the second '()' calls it immediately

3. Loops

Once you have an array of data, you can loop through it with several ways in Javascript:

The classic for loop

A for loop has three parts: initialisation, condition, and increment.

const fruits = ["apple", "banana", "cherry"];

for (let i = 0; i < fruits.length; i++) {
    console.log(i + ": " + fruits[i]);
}
// 0: apple
// 1: banana
// 2: cherry

This is the most flexible loop — you control the counter, the step, and when to stop. But for simple "do something with every item" tasks, there are easier options.

for...of

If you don't need the index and just want each value, you can use for...of. This is similar to what we have in Python for item in list

for (const fruit of fruits) {
    console.log(fruit);
}

.forEach() — a method on arrays

Call .forEach() on an array and pass it a function. That function runs once for every item:

fruits.forEach(function(fruit, index) {//this is a callback function as well
    console.log(index + ": " + fruit);
});
// Same output as the for loop above

// With an arrow function (shorter):
fruits.forEach((fruit, i) => console.log(i + ": " + fruit));

You can also use forEach() to iterate over a javascript object:

const obj = {
    name: "Peter",
    age: 23,
    hobbies: ["cycling","reading","dreaming"]
};

// get an array of object keys using Object.keys()
const keys = Object.keys(obj); 

keys.forEach(function(key) { // then use forEach() on this array 
    console.log(key, obj[key]);
});

forEach is often the cleanest choice to loop through an array and is more native to Javascript.

5. HTTP Requests — Talking to the Internet

So far all our data has been hard-coded in a <script> tag. Real apps get data from local files or servers. They do this with HTTP requests.

fetch() — the built-in way to make requests

fetch() sends a request to a URL and returns a promise that eventually resolves with the server's response:

// The simplest fetch — get data from a URL
fetch("https://jsonplaceholder.typicode.com/users/1")
    .then(response => response.json())   // parse the JSON body
    .then(data => {
        console.log(data.name);           // "Leanne Graham"
        console.log(data.email);          // "Sincere@april.biz"
    })
    .catch(error => console.error("Something went wrong:", error));

Let's unpack that step by step:

  1. fetch(url) — sends a GET request, returns a promise
  2. .then(response => response.json()) — the server replies; we extract the JSON body (this also returns a promise)
  3. .then(data => {…}) — now we have the actual data and can use it
  4. .catch(…) — if anything fails (no internet, server down), this runs

Sending data with POST

GET requests ask for data. POST requests send data to the server (e.g. submitting a form):

fetch("https://jsonplaceholder.typicode.com/posts", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    // when we try to send a javascript object, we always stringify it to a json string
    body: JSON.stringify({ 
        title: "My Post",
        body: "Hello, world!",
        userId: 1
    })
})
    .then(r => r.json())
    .then(data => console.log("Created:", data));

6. Async & Delay

JavaScript is single-threaded, which means it can only do one thing at a time. But why do websites feel responsive while loading data? Because JavaScript doesn't wait — it schedules work for later and keeps going.

setTimeout() — run something after a delay

console.log("A");
setTimeout(function(){
    console.log("B (2 seconds later)");
}, 2000);  // 2000 milliseconds = 2 seconds
console.log("C");

// Output:
// A
// C
// B (2 seconds later)
Click to see the order of execution…

setInterval() — repeat something at regular intervals

// Print the time every second
const timer = setInterval(function(){
    console.log(new Date().toLocaleTimeString());
}, 1000);

// Stop after 5 seconds
setTimeout(function(){
    clearInterval(timer);
    console.log("Stopped.");
}, 5000);

async / await — a cleaner way to handle promises

Instead of chaining .then() calls, you can now do this in more elegant way by using await. 

// With .then() --> the "old" way
function getUser(id) {
    fetch(`https://jsonplaceholder.typicode.com/users/${id}`)
        .then(r => r.json())
        .then(user => console.log(user.name));
}

// With async/await --> the modern, cleaner way
async function getUser(id) {
    const response = await fetch(`https://jsonplaceholder.typicode.com/users/${id}`);
    const user = await response.json();
    console.log(user.name);
}
// Both do exactly the same thing.
Rule: You can only use await inside a function declared with async. At the top level of a script, you still need .then() — or you can wrap your code in an async IIFE: (async () => { … })().
